# Промпт: сайт SkyNational Community

> Полный технический бриф для разработки сайта. Все решения уже согласованы с владельцелем проекта.

---

## 1. Что это за проект

**SkyNational Community** — сообщество виртуальных пилотов, летающих в сетевых авиасимуляторах на сети **VATSIM / IVAO**.

Сайт community — это **витрина + набор персонала + информационный хаб** (новости, анонсы событий).

### Сайт обязан
- красиво представить сообщество (что это, чем занимается, чего достигло);
- набирать персонал: показывать открытые вакансии и принимать заявки;
- публиковать новости и анонсировать события/слёты;
- давать базу знаний (wiki/обучение) и внешние ссылки на площадки сообщества.

### Сайт НЕ должен делать (жёсткие ограничения)
- ❌ расписания полётов, рейтинги, налёт, статистику пилотов;
- ❌ личные кабинеты, авторизацию, профили;
- ❌ бэкенд, базу данных, серверную логику;
- ❌ платформенные фичи (форум, комментарии, чат);
- ❌ трекеры аналитики, рекламу, куки-баннеры.

## 2. Технический стек (согласовано)

| Параметр | Решение |
|---|---|
| Фреймворк | **Astro** (static output, `output: 'static'`) |
| Язык | Astro components + TypeScript, стили — CSS (SCSS допустим) |
| Контент | **Markdown** с frontmatter (новости, события, статьи wiki) |
| Данные | JSON/TS-конфиги для вакансий, соцсетей, настроек |
| Поиск | Клиентский (MiniSearch или Fuse.js), индекс генерируется при сборке |
| Переводы | Полностью статический сайт |
| Структура | Проект лежит в папке **`skynational/`** текущего репозитория |
| Хостинг | **GitHub Pages** (`*.github.io`), base path под имя репозитория |
| Деплой | **GitHub Actions**: push → build → publish на Pages |

Разрешённые зависимости: Astro, мини-библиотеки поиска, иконки (например `@iconify-json/*` или inline SVG). Никаких React/Vue-приложений, тяжёлых UI-фреймворков и CSS-фреймворков «всё включено».

## 3. Языки (i18n)

- Два языка: **ru (по умолчанию)** и **en**.
- Роутинг: `/` … `/contacts` — русский, `/en` … `/en/contacts` — английский. Без префикса у русского.
- Переключатель языка в шапке; выбор сохраняется в `localStorage`, при повторном визите — редирект на сохранённый язык.
- Весь UI (меню, кнопки, подписи, формы, ошибки валидации) — в словарях `i18n/ru.json` и `i18n/en.json`.
- Контент: у Markdown-материалов frontmatter содержит и `title_ru`/`title_en` (или вложенные блоки RU/EN). Пока английский текст не получен — применяется перевод, при получении оригинала заменяется.
- `<html lang>` корректно меняется, hreflang-альтернативы и canonical — на каждой странице.

## 4. Дизайн и айдентика

- **Палитра: синий / голубой / белый.** Базовый режим — **светлый** (белый фон, синие акценты, как у сайта авиакомпании), доступен **переключатель тёмной темы** (глубокий тёмно-синий фон, голубые акценты, белый текст). Тема хранится в `localStorage`, уважает `prefers-color-scheme`.
- Типографика: современный гротеск (например Inter / Manrope, подключить локально или через `fontsource`), широкая заголовочная сетка, читаемые межстрочные.
- Авиационная стилистика: лёгкие «приборные» детали (метки, тонкие рамки, коды IATA/позывные как декор), никакой дешёвой неонщины.
- **Ассеты будут предоставлены владельцем** (логотип, фото). До их получения — аккуратные заглушки с **точно совпадающими именами файлов и путями**, чтобы замена произошла 1-в-1 без правки кода. Логотип в шапке/подвале + favicon + OG-image.
- Адаптив: mobile-first, бургер-меню на мобильных, все блоки проверены на 320–1920px.

### Анимации и эффекты (согласовано)
- Появление секций при скролле (IntersectionObserver / `astro:is` — без тяжёлых библиотек), лёгкий параллакс/фон неба в hero.
- Hover-состояния карточек, плавные переходы, микроанимации кнопок.
- Обязательно: `@media (prefers-reduced-motion: reduce)` отключает всё анимированное.

## 5. Страницы и их содержимое

### 5.1 Главная (`/`)
- Hero: логотип, название **SkyNational Community**, слоган, 2 CTA — «Присоединиться» и «Новости».
- Блок ключевых фактов о сообществе (год основания, сети VATSIM/IVAO, формат, направления).
- «О сообществе» — короткий текст со ссылкой на страницу.
- Три последние новости (карточки с датой и тегами).
- Ближайшее/последнее событие с датой и обратным отсчётом, ссылка «Все события».
- Блок открытых вакансий (мини-карточки + «Смотреть все»).
- CTA-баннер «Стать частью SkyNational».
- Счётчик онлайна Discord (см. §7).

### 5.2 О сообществе (`/about`)
История, миссия и ценности, структура сообщества, сети VATSIM/IVAO, достижения и события, галерея-превью, партнёры/дружественные сообщества.

### 5.3 Вакансии и команда (`/vacancies`)
- Все роли карточками. Список фиксированный:

| Код | Название |
|---|---|
| CFO | Chief Financial Officer |
| CCO | Chief Commercial Officer |
| CGO | Chief Growth Officer |
| CSO | Chief Security Officer |
| CHO | Chief Human Officer |
| CDO | Chief Development Officer |
| CUR | Curator ADM/MODR |
| SUP | Support-Ticket |
| SCD | Moderator |

- Описания ролей (обязанности, требования, что предлагаем) **даёт владелец проекта** — структура полей в `vacancies.json` должна быть готова принять их: `id, code, title_ru, title_en, desc_ru, desc_en, responsibilities[], requirements[], benefits[], open: boolean`.
- У каждой карточки — статус (открыта/закрыта) и кнопка «Откликнуться», ведущая на `/join` с предвыбранной вакансией (`/join?vacancy=cfo`).
- Раздел «Команда»: уже занятые роли / руководство (данные из того же JSON).

### 5.4 Новости (`/news`, `/news/[slug]`)
- Лента: карточки с датой, обложкой, тегами; **фильтрация по тегам** (события, обновления, рекрутинг, анонсы — реализовать как набор тегов во frontmatter).
- Страница новости: заголовок, дата, теги, автор, обложка, тело Markdown, ссылки «поделиться», кнопки «назад в ленту», блок «читайте также».

### 5.5 События (`/events`)
- Список событий/слётов/групповых полётов: дата и время (с таймзоной), тип, маршрут/аэропорт вылета-назначения, сети (VATSIM/IVAO), ссылка (Discord-ивент и т.п.).
- Разделение на «предстоящие» и «прошедшие», сортировка по дате, ближайшее событие выделено.
- Frontmatter события: `title_ru/title_en, date, endDate?, timezone, type, route?, network?, link?, desc_ru/desc_en`.

### 5.6 Wiki (`/wiki`, `/wiki/[slug]`)
- **Категории → статьи** (категории: напр. «Начало работы», «Полёты в сети», «Регламенты сообщества», «Оборудование и софт», «Диспетчерирование»).
- Главная wiki: плитки категорий, поиск по заголовкам/содержимому, недавние статьи.
- Статья: оглавление, хлебные крошки, «назад к категории», блок «полезно/нет» не нужен.
- Структура wiki: `title_ru/title_en, category, order, desc_ru/desc_en, tags`.

### 5.7 Присоединиться (`/join`)
Форма-анкета (см. §6).

### 5.8 Контакты (`/contacts`)
Иконки и ссылки на все площадки, блок с Discord-инвайтом, Telegram, VATSIM/IVAO-профилями, YouTube/Twitch; общая форма обратной связи (та же отправка в Discord); копирайт и юридические мелочи.

## 6. Форма заявки (Discord Webhook)

**Поля (все согласованы):**
1. Discord ник — *обязательное*
2. Выбор вакансии — выпадающий список из 9 ролей кодов (§5.3), *обязательное*
3. Возраст — *обязательное*, число
4. Часовой пояс / регион — *обязательное*
5. Опыт и налёт (где летал, VATSIM/IVAO, прежние сообщества) — textarea, *обязательное*
6. Мотивация — textarea, *обязательное*
7. Ссылки на профили (VATSIM/IVAO, Telegram, YouTube…) — *необязательное*
8. Имя и email — *необязательное*

**Поведение:**
- Отправка **POST на Discord Webhook** (`https://discord.com/api/webhooks/…`). URL хранится в `src/config.ts` как `DISCORD_WEBHOOK_URL`, до получения — пустая строка с `TODO`; при пустом вебхуке форма показывает сообщение «Отправка временно недоступна, напишите в Discord» и предлагает кнопку-копирование анкеты (фолбэк).
- Валидация на клиенте (required-поля, возраст — число, email — формат), сообщения об ошибках переводятся.
- Ошибки сети и успех показываются inline без перезагрузки страницы, кнопка блокируется на время отправки.
- Анти-спам: honeypot-поле (скрытое) + защита от повторной отправки (кнопка недоступна N секунд).
- Webhook: отправляется embed с заголовком «Новая заявка — {роль}», списком полей и цветом акцента; на каждое поле отдельный field, упоминание роли через `<@&roleID>` — опционально (поле `MENTION_ROLE_ID` в конфиге).
- **Важно:** URL вебхука уходит в клиентский бандл — это допустимо для публичной формы приёма заявок, но в конфиге должно быть прямо написано, что его надо перевыпустить при утечке спама.

## 7. Внешние интеграции (без бэкенда)

- **Счётчик онлайна Discord**: клиентский fetch `https://discord.com/api/guilds/{GUILD_ID}/widget.json` → `presence_count` + `members.online`. Если ID не задан или запрос упал — блок не рендерится (без «0» и без ошибок в консоли). Скелетон-плейсхолдер до ответа.
- **Ссылки** (в шапке/подвале/контактах, всё в `socials`-конфиге): Discord (инвайт), Telegram, VATSIM, IVAO, YouTube/Twitch. Метки, иконки, `rel="noopener noreferrer"` + `target="_blank"`.
- **Поиск по сайту**: модалка/панель, открывается по кнопке в шапке и по `Ctrl/Cmd+K`. Ищет по страницам, новостям, событиям и wiki; индекс (JSON) собирается на этапе сборки; подсветка совпадений, клавиатурная навигация, пустое состояние.

## 8. Контент (средний объём)

Заглушки для живости сайта (заменяются реальными материалами владельца):
- **3–5 новостей** (разные даты, разные теги);
- **2–3 события** (одно предстоящее, остальные — прошедшие);
- **6–8 статей wiki** минимум в 4 категориях;
- **все 9 вакансий**;
- **6–9 фотографий** галереи;
- тексты «О сообществе» — TODO-заглушки, помеченные в коде комментарием, пока владелец не пришлёт свои.

Галерея: masonry/сетка с лайтбоксом, подписи (автор, борт, маршрут), lazy-loading.

**Владелец пришлёт реальные тексты в чат и файлы изображениями** — структура проекта должна позволять заменить их без переписывания кода (контент в `src/content/`, картинки в `public/assets/` с фиксированными именами).

## 9. Качество: SEO, производительность, доступность

- **SEO**: `<title>`/`<meta description>` на каждой странице (i18n), canonical, hreflang ru/en, Open Graph + Twitter cards, `sitemap.xml`, `robots.txt`, семантическая разметка (один `h1`, логичные уровни заголовков).
- **Производительность**: Lighthouse Performance/SEO/Best Practices ≥ 95, изображения в AVIF/WebP с `width/height` и `loading="lazy"`, критический CSS инлайном, никаких тяжёлых JS-бандлов — интерактив (поиск, форма, переключатели) грузится лениво.
- **Доступность**: контраст ≥ WCAG AA, фокус-стили, `aria-label` у иконочных кнопок, клавиатурная навигация, форма с `<label>` и `aria-describedby` для ошибок.
- Код: TypeScript, единый стиль (Prettier), переиспользуемые компоненты, никакого дублирования разметки между RU и EN страницами.

## 10. Деплой

1. `npm run dev` — локальный превью, `npm run build` + `npm run preview` — проверка статики.
2. `.github/workflows/deploy.yml`: on push to main → `npm ci` → `npm run build` → `actions/deploy-pages`.
3. `astro.config.mjs`: `site: 'https://<OWNER>.github.io'`, `base: '/<REPO>'` (заполнить под реальный репозиторий), плюс переменная `BASE_PATH`, чтобы пути работали и локально.
4. README в `skynational/`: как запустить, как добавить новость/статью/вакансию, где менять webhook и ссылки.

## 12. Чего делать не нужно

- Не изобретать расписания, рейтинги, статистику пилотов и профили.
- Не подключать базы данных, серверные API, авторизацию.
